# 灵感收纳盒 · 数据备份指南

> 版本：V1.4.3 | 更新日期：2026-10-30
> 一句话原则：**浏览器只是"工作台"，不是"保险箱"。数据只有在"本机 + 文件 + 密文云端"三处至少占两处，才真正安全。**

---

## 一、为什么这个 App 必须重视备份

我们的产品是纯前端单文件应用，数据存在浏览器 IndexedDB 里。V1.3 起虽然多了加密云同步，但**没开启同步、或忘记同步密码时**，以下情况仍会导致数据永久丢失：

| 风险场景 | 后果 | 有云同步时 |
|---|---|---|
| 清理浏览器缓存/浏览数据 | IndexedDB 被清空，全丢 | 可从云端密文恢复（须记得同步密码） |
| 卸载重装浏览器、换浏览器 | 数据不跟着走 | 令牌+密码重新配置即可拉回 |
| 换电脑 / 换手机 | 数据留在旧设备 | 新设备配置后自动拉回 |
| 误删 index.html 文件 | 作品本身没了 | GitHub 仓库有全部历史版本 |
| 浏览器异常崩溃（图片存太多） | 数据库可能损坏 | 云端密文 + 本地 JSON 双保险 |
| 忘记同步密码 | —— | 云端密文无法解开，只能靠本地 JSON |

**所以要备份三样东西**：① 数据（JSON 导出文件，永远的最后防线）；② 作品（index.html 本身，GitHub 仓库已托管）；③ 开启端到端加密云同步（防设备丢失，不替代文件备份）。

## 二、三层备份体系（纵深防御）

### 第一层：应用内备份（保护数据）

**V1.0 已有**：顶部栏常驻「导出 JSON」「导入」按钮，导出内容 = IndexedDB 全量数据（含被折叠的子素材，一条不落）。

**V1.1 计划加入的自动备份功能**（写在代码里，下次迭代加上）：

| 方案 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| A. 修改后自动导出 | 每次"封存"新碎片后，自动触发一次 JSON 下载 | 零配置、所有浏览器可用 | 下载文件夹会积累文件，需定期清理 |
| B. 静默文件夹备份 | 用 File System Access API 授权一个备份文件夹（如 E 盘 backups），之后每次修改自动静默写入 | 真正的"无感自动备份" | 仅 Chrome/Edge 支持，Safari（iPad）不支持 |
| C. 备份提醒红点 | 界面显示"距上次导出已 X 天 / 已有 N 条未备份"，超 3 天变红 | 成本最低，养成习惯 | 需要人动手点 |

**已确认采用「方案 1 + 方案 2」去重组合（2026-10-29）**：

1. **变更检测**：每次封存后先算数据 hash，与 settings 表的 `lastBackupHash` 比对，**数据没变就不备份**——重复备份从源头不产生；
2. **Chrome/Edge（电脑）**：授权一次备份文件夹后，静默**覆盖写入** `inspiration-backup-latest.json`（永远只有一份、永远最新）；每 7 天额外归档一份 `inspiration-backup-YYYY-MM-DD.json` 防误覆盖；
3. **Safari（iPad）回退**：普通下载固定文件名 `inspiration-backup-latest.json`，浏览器会自动加 (1)(2) 序号，每周整理时保留最新一份即可。

> 为什么不做"增量备份/只备份新增内容"？恢复时要按顺序拼接备份链，任何一环缺失全崩。全量 JSON 只有几 MB，备份的第一原则是**恢复简单**，不是省空间。

### 第二层：本地文件备份（保护作品）

项目目录规范：

```
E:\Projects\Inspiration Inbox\
├── app\index.html          ← 当前作品
├── docs\                   ← 所有文档
└── backups\
    ├── code\               ← 代码历史版本
    │   ├── index-v1.0-20261029.html
    │   └── index-v2.0-20261105.html
    └── data\               ← 数据备份
        ├── inspiration-backup-2026-10-29.json
        └── inspiration-backup-2026-10-30.json
```

规则：
1. **每完成一个开发任务**（见提示词手册的任务划分），立刻复制一份 index.html 到 `backups\code\`，文件名带版本号和日期；
2. **每次导出 JSON**，顺手把它从"下载"文件夹移到 `backups\data\`；
3. `backups` 里**永不删除**旧版本——硬盘空间不值钱，灵感无价。

### 第三层：异地 / 云端备份（防电脑损坏、丢失）

| 渠道 | 备份什么 | 频率 |
|---|---|---|
| GitHub 仓库 | index.html + docs（代码与文档） | 每个版本完成时 |
| GitHub Pages | 顺便获得一个永久网址，手机也能打开 | 同上 |
| **GitHub Gist（V1.3 起）** | **端到端加密后的全量数据密文，三端自动同步** | **每次改动后自动（防抖 5 秒）** |
| 微信"文件传输助手" | 最新 JSON + index.html 发给自己 | 应急，随时 |
| U盘 / 移动硬盘 | 整个项目文件夹 | 每周一次 |
| 网盘（百度/OneDrive） | 整个项目文件夹 | 每周一次 |

> 注意：云同步不改变"数据主权"——Gist 里只有 AES-256 密文，密钥由用户的同步密码派生，GitHub 与应用作者都无法阅读；随时可吊销令牌、删除 Gist。本地文件备份仍然不废，它是"忘记同步密码"时的唯一后路。

## 三、日常备份 SOP（每次开发后 3 分钟）

1. 在 App 里点「导出 JSON」→ 移到 `backups\data\`；
2. 复制 `app\index.html` → `backups\code\index-v版本号-日期.html`；
3. 重要节点（如 V1.0 完成）：项目文件夹压缩一份发微信/U盘/GitHub。

**每周固定动作**（建议周日晚上）：检查 backups 里是否有本周的 JSON；上传一次 GitHub 或网盘。

## 四、灾难恢复演练（重要！）

备份文件只有"验证过能恢复"才算数。每月做一次演练：

1. 在 App 里手动删除一两条不重要的测试数据；
2. 点「导入」，选择最近一次 JSON 备份；
3. 确认被删的数据回来了；
4. 如果恢复失败，说明备份流程有漏洞，立刻排查。

## 五、常见问题（FAQ）

**Q1：我不小心清了浏览器缓存，数据全没了怎么办？**
只要有过 JSON 导出：打开 index.html → 点「导入」→ 选最近的备份文件 → 全部恢复。没导出过就救不回——这就是把导出按钮放在顶部常驻的原因。

**Q2：换电脑/换浏览器，数据能带走吗？**
能。数据不绑定设备，跟着 JSON 文件走：旧设备导出 → 文件拷贝/微信发送 → 新设备导入。

**Q3：手机/iPad 上导出的文件去哪找？**
- iPad Safari：下载后存到"文件"App 的"下载"文件夹，建议立刻移动到"我的 iPad"里的固定文件夹；
- 安卓：在"下载"目录，可用文件管理器移动。

**Q4：JSON 备份文件安全吗？别人拿到能看到内容吗？**
JSON 是明文，拿到文件就能读。涉及私密灵感时：不要把 JSON 传到不信任的公共网盘；U盘/本地备份最安全。

**Q5：图片存太多，IndexedDB 会不会撑爆？**
代码里已做 Canvas 压缩，几百张图没问题。但建议每季度做一次"大扫除"：导出 JSON → 删除不再需要的图片碎片 → 重新导入。

**Q6：完全断网时还能用吗？（V1.3.5）**
可以，这是本地优先设计的核心：封存文字/图片、标签、三空间、搜索、删除、日夜切换、导出/导入全部离线可用（桌面 App 需之前联网打开过一次完成缓存）。只有云同步暂停——改动存在本机并记下删除墓碑，联网恢复后 1～2 秒自动补传与拉取；断网时手动点云同步会看到"网络不通"提示，不影响录入。三端断网各自录入，恢复后按最后修改时间自动合并。

## 六、多端使用与浏览器兼容性指南

### 6.1 各端打开方式

单文件 HTML 是全浏览器通用格式，代码侧已做响应式布局、`-webkit-` 前缀（Safari 毛玻璃）和功能特性检测自动降级，**任何现代浏览器都能运行**。各端打开方式：

| 设备 | 打开方式 | 注意事项 |
|---|---|---|
| 电脑 Windows/Mac | 双击 index.html | 推荐 Chrome/Edge（可启用覆盖式静默备份） |
| 安卓手机 | 微信/QQ 传文件 → 保存到本地 → 文件管理器中选"用 Chrome 打开" | 避免用微信内置浏览器打开（下载、文件权限不顺畅） |
| iPad / iPhone | 文件传到"文件"App → 打开时选择用 Safari 打开 | iOS 对本地 HTML 天然不友好；下载的 JSON 在"文件"App 的"下载"里 |
| 终极解法 | 上传 GitHub Pages，全端用网址打开 | 最顺滑；公开的是"空壳 App"，数据仍存各自浏览器本地，别人打开看不到你的数据 |

### 6.2 各端备份能力对照表（重要）

| 能力 | 电脑 Chrome/Edge | 安卓手机 Chrome | iPhone/iPad Safari |
|---|---|---|---|
| 静默覆盖写 latest.json | ✅ 授权一次文件夹后永久无感 | ❌ 手机端不支持选文件夹 | ❌ 不支持 |
| 自动备份实际行为 | 覆盖写入文件夹 | **自动降级：下载 latest.json** | **自动降级：下载到"文件"App** |
| 持久化可靠性 | 可靠 | 可靠 | 本地文件方式不可靠，须用网址打开 |
| 用户动作 | 仅首次授权 | 定期把下载文件移到安全位置 | 同左；另注意 Safari 约 7 天不用可能清理网站数据，每周至少打开一次 |

### 6.3 关键认知：数据跨设备机制（V1.3 起已升级）

IndexedDB 仍存在**每台设备各自的浏览器**里（浏览器按来源隔离，Safari 标签页与主屏幕 App 也是两个库），这一点没有变；变的是上面多了一层**可选的、端到端加密的自动同步**（见 6.4.1）。

三种搬运方式并存：

```
① 云同步（推荐）：各端配置同一令牌+同步密码 → 自动双向合并，断网照录、联网补传
② 文件搬家（不依赖云）：旧设备导出 JSON → 微信/QQ/隔空投送/U盘 → 新设备导入 JSON
③ 应急：微信文件传输助手发 latest.json
```

推荐用法：**电脑作为主库**（Chrome + 授权文件夹无感备份）+ 三端开启云同步；手机/iPad 随时录入，自动汇聚。云同步是"多一份密文副本"，文件备份习惯不取消。

> 理念注记：V1.0 文档曾写"自动云同步 V1.x 阶段不做"。2026-10-30 三端真机日常使用后改为**本地优先（local-first）+ 零知识云同步**：本地库永远是主体，断网全功能可用；云端只是加密信箱。论述素材见 docs/07。

### 6.4.1 三端云同步（V1.3 起可选开启，V1.3.5 三端真机验证通过）

本地优先的底子不变（断网照常记录），联网后通过 **GitHub Gist（秘密、不公开）+ AES-256-GCM 端到端加密**自动三端同步。技术细节见 docs/04 第五节。

**工作机制**：
- 同步前用"同步密码"经 PBKDF2（15 万次）派生密钥加密，GitHub 上看到的是乱码；三端使用同一令牌、同一同步密码；
- 合并规则：每条碎片按唯一 id 合并，"最后修改时间"新者胜出；删除通过"墓碑"同步（30 天内有效），不会在别的设备复活；
- 自动同步时机（V1.3.5）：启动后 1.5 秒、封存/删除/导入后 5 秒（防抖）、恢复联网时、**切回窗口/回前台/pageshow 约 1.2 秒、页面可见时每 45 秒轮询**；也可点顶栏「☁ 云同步」立即同步；
- 同步请求强制 no-store，不读浏览器缓存；
- **省流提速（V1.4.2）**：同步文件随图片增多接近 1MB 时，旧版空闲轮询也要反复整包下载+上传，慢网络下会长时间显示"同步中"。现改为 ETag 304 条件拉取（云端没变只回几百字节）+ 本地状态指纹去重（没变就不上传）；只有真有改动时才传输整包，45 秒轮询因此几乎零开销；
- 第二、三台设备无需填 Gist 地址，输入令牌+密码后会自动发现同步文件；
- 限额：GitHub API 每小时 5000 次（三端常开每天仅数百次，远用不完）；单个同步文件建议 10MB 内（压缩图片约几十张），纯文本几乎无上限。

**配置步骤（每台设备一次，约 1 分钟）**：
1. 在能访问 GitHub 的网络下，用已登录 GitHub 的浏览器打开（已自动勾好 gist 权限）：
   `https://github.com/settings/tokens/new?scopes=gist&description=Inspiration-Inbox`
2. Note 已自动填好；Expiration 建议选 **No expiration（永不过期）**，省事（仅 gist 权限，风险低），介意可选 90 天；其他 scope 一律不勾 → Generate token → 复制 `ghp_` 开头的令牌（只显示一次）；
3. 打开 App → 顶栏「☁ 云同步」→ 粘贴令牌 → 设置一个**同步密码**（三端一致，记牢，遗忘后云端文件无法解开，但本机数据不受影响）→ 保存并立即同步；
4. 其他两台设备重复第 3 步（令牌共用同一个；iPad 主屏幕 App 是独立数据容器，需要在 App 内单独配一次）。手机上令牌较长，建议微信"文件传输助手"发到手机再粘贴。

**常见问题**：
- 提示"令牌无效 / 401"：令牌没复制全、没勾 gist 或已过期；随时可在 GitHub 吊销重建，本地数据不受影响。
- 提示"解密失败/密码错误"：三端同步密码必须完全一致（无空格、区分大小写）。
- 同步失败提示网络不通：同步的一瞬间需要能访问 GitHub；记录动作本身离线可用，联网后自动补传。
- 「取消本机同步配置」只删本机令牌与密码，不删本地数据、不删云端 Gist。
- **零知识架构没有"忘记密码"**：密码不可找回（Joplin/Standard Notes 同理），记到安全的地方；忘了就靠 JSON 备份。

**局域网临时试用（备用）**：电脑与手机连同一 Wi-Fi，电脑在 app 目录运行 `python -m http.server 8765 --bind 0.0.0.0`（允许防火墙弹窗），手机浏览器访问 `http://电脑IP:8765`（cmd 运行 ipconfig 查 IPv4 地址）。

**版本查看**：GitHub 仓库的 Commits 页面是每次改动的完整历史；重要版本会打 tag（如 v1.0），在 Releases/Tags 中可下载任意历史版本的完整代码包。

### 6.5 用户操作清单（代码之外需要你做的事）
