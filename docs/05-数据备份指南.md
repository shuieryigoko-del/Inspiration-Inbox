# 灵感收纳盒 · 数据备份指南

> 版本：V1.0 | 整理日期：2026-10-29
> 一句话原则：**浏览器只是"工作台"，不是"保险箱"。数据只有导出成文件，才真正属于你。**

---

## 一、为什么这个 App 必须重视备份

我们的产品是纯前端单文件应用，数据存在浏览器 IndexedDB 里。以下情况**都会导致数据永久丢失**：

| 风险场景 | 后果 |
|---|---|
| 清理浏览器缓存/浏览数据 | IndexedDB 被清空，全丢 |
| 卸载重装浏览器、换浏览器 | 数据不跟着走 |
| 换电脑 / 换手机 | 数据留在旧设备 |
| 误删 index.html 文件 | 作品本身没了 |
| 浏览器异常崩溃（图片存太多） | 数据库可能损坏 |

**所以要备份两样东西**：① 数据（JSON 导出文件）；② 作品（index.html 本身）。

## 二、三层备份体系（纵深防御）

### 第一层：应用内备份（保护数据）

**V1.0 已有**：顶部栏常驻「导出 JSON」「导入」按钮，导出内容 = IndexedDB 全量数据（含被折叠的子素材，一条不落）。

**V1.1 计划加入的自动备份功能**（写在代码里，下次迭代加上）：

| 方案 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| A. 修改后自动导出 | 每次"封存"新碎片后，自动触发一次 JSON 下载 | 零配置、所有浏览器可用 | 下载文件夹会积累文件，需定期清理 |
| B. 静默文件夹备份 | 用 File System Access API 授权一个备份文件夹（如 E 盘 backups），之后每次修改自动静默写入 | 真正的"无感自动备份" | 仅 Chrome/Edge 支持，Safari（iPad）不支持 |
| C. 备份提醒红点 | 界面显示"距上次导出已 X 天 / 已有 N 条未备份"，超 3 天变红 | 成本最低，养成习惯 | 需要人动手点 |

**已确认采用「方案 1 + 方案 2」去重组合（2026-10-29）**：

1. **变更检测**：每次封存后先算数据 hash，与 settings 表的 `lastBackupHash` 比对，**数据没变就不备份**——重复备份从源头不产生；
2. **Chrome/Edge（电脑）**：授权一次备份文件夹后，静默**覆盖写入** `inspiration-backup-latest.json`（永远只有一份、永远最新）；每 7 天额外归档一份 `inspiration-backup-YYYY-MM-DD.json` 防误覆盖；
3. **Safari（iPad）回退**：普通下载固定文件名 `inspiration-backup-latest.json`，浏览器会自动加 (1)(2) 序号，每周整理时保留最新一份即可。

> 为什么不做"增量备份/只备份新增内容"？恢复时要按顺序拼接备份链，任何一环缺失全崩。全量 JSON 只有几 MB，备份的第一原则是**恢复简单**，不是省空间。

### 第二层：本地文件备份（保护作品）

项目目录规范：

```
E:\Projects\Inspiration Inbox\
├── app\index.html          ← 当前作品
├── docs\                   ← 所有文档
└── backups\
    ├── code\               ← 代码历史版本
    │   ├── index-v1.0-20261029.html
    │   └── index-v2.0-20261105.html
    └── data\               ← 数据备份
        ├── inspiration-backup-2026-10-29.json
        └── inspiration-backup-2026-10-30.json
```

规则：
1. **每完成一个开发任务**（见提示词手册的任务划分），立刻复制一份 index.html 到 `backups\code\`，文件名带版本号和日期；
2. **每次导出 JSON**，顺手把它从"下载"文件夹移到 `backups\data\`；
3. `backups` 里**永不删除**旧版本——硬盘空间不值钱，灵感无价。

### 第三层：异地 / 云端备份（防电脑损坏、丢失）

| 渠道 | 备份什么 | 频率 |
|---|---|---|
| GitHub 仓库 | index.html + docs（代码与文档） | 每个版本完成时 |
| GitHub Pages | 顺便获得一个永久网址，手机也能打开 | 同上 |
| 微信"文件传输助手" | 最新 JSON + index.html 发给自己 | 应急，随时 |
| U盘 / 移动硬盘 | 整个项目文件夹 | 每周一次 |
| 网盘（百度/OneDrive） | 整个项目文件夹 | 每周一次 |

> 注意：云端只放"备份文件"，App 本身永远是本地运行——这不违背"数据主权"理念，因为文件是你的，随时可以删掉云端副本。

## 三、日常备份 SOP（每次开发后 3 分钟）

1. 在 App 里点「导出 JSON」→ 移到 `backups\data\`；
2. 复制 `app\index.html` → `backups\code\index-v版本号-日期.html`；
3. 重要节点（如 V1.0 完成）：项目文件夹压缩一份发微信/U盘/GitHub。

**每周固定动作**（建议周日晚上）：检查 backups 里是否有本周的 JSON；上传一次 GitHub 或网盘。

## 四、灾难恢复演练（重要！）

备份文件只有"验证过能恢复"才算数。每月做一次演练：

1. 在 App 里手动删除一两条不重要的测试数据；
2. 点「导入」，选择最近一次 JSON 备份；
3. 确认被删的数据回来了；
4. 如果恢复失败，说明备份流程有漏洞，立刻排查。

## 五、常见问题（FAQ）

**Q1：我不小心清了浏览器缓存，数据全没了怎么办？**
只要有过 JSON 导出：打开 index.html → 点「导入」→ 选最近的备份文件 → 全部恢复。没导出过就救不回——这就是把导出按钮放在顶部常驻的原因。

**Q2：换电脑/换浏览器，数据能带走吗？**
能。数据不绑定设备，跟着 JSON 文件走：旧设备导出 → 文件拷贝/微信发送 → 新设备导入。

**Q3：手机/iPad 上导出的文件去哪找？**
- iPad Safari：下载后存到"文件"App 的"下载"文件夹，建议立刻移动到"我的 iPad"里的固定文件夹；
- 安卓：在"下载"目录，可用文件管理器移动。

**Q4：JSON 备份文件安全吗？别人拿到能看到内容吗？**
JSON 是明文，拿到文件就能读。涉及私密灵感时：不要把 JSON 传到不信任的公共网盘；U盘/本地备份最安全。

**Q5：图片存太多，IndexedDB 会不会撑爆？**
代码里已做 Canvas 压缩，几百张图没问题。但建议每季度做一次"大扫除"：导出 JSON → 删除不再需要的图片碎片 → 重新导入。

## 六、多端使用与浏览器兼容性指南

### 6.1 各端打开方式

单文件 HTML 是全浏览器通用格式，代码侧已做响应式布局、`-webkit-` 前缀（Safari 毛玻璃）和功能特性检测自动降级，**任何现代浏览器都能运行**。各端打开方式：

| 设备 | 打开方式 | 注意事项 |
|---|---|---|
| 电脑 Windows/Mac | 双击 index.html | 推荐 Chrome/Edge（可启用覆盖式静默备份） |
| 安卓手机 | 微信/QQ 传文件 → 保存到本地 → 文件管理器中选"用 Chrome 打开" | 避免用微信内置浏览器打开（下载、文件权限不顺畅） |
| iPad / iPhone | 文件传到"文件"App → 打开时选择用 Safari 打开 | iOS 对本地 HTML 天然不友好；下载的 JSON 在"文件"App 的"下载"里 |
| 终极解法 | 上传 GitHub Pages，全端用网址打开 | 最顺滑；公开的是"空壳 App"，数据仍存各自浏览器本地，别人打开看不到你的数据 |

### 6.2 各端备份能力对照表（重要）

| 能力 | 电脑 Chrome/Edge | 安卓手机 Chrome | iPhone/iPad Safari |
|---|---|---|---|
| 静默覆盖写 latest.json | ✅ 授权一次文件夹后永久无感 | ❌ 手机端不支持选文件夹 | ❌ 不支持 |
| 自动备份实际行为 | 覆盖写入文件夹 | **自动降级：下载 latest.json** | **自动降级：下载到"文件"App** |
| 持久化可靠性 | 可靠 | 可靠 | 本地文件方式不可靠，须用网址打开 |
| 用户动作 | 仅首次授权 | 定期把下载文件移到安全位置 | 同左；另注意 Safari 约 7 天不用可能清理网站数据，每周至少打开一次 |

### 6.3 关键认知：数据不跨设备同步（刻意设计）

IndexedDB 存在**每台设备各自的浏览器**里，互不相通。这是"绝对本地"的代价，也是隐私的保障。

换设备/换浏览器的搬运流程：

```
旧设备：导出 JSON → 微信/QQ/隔空投送/U盘 传输文件 → 新设备：打开 App → 导入 JSON
```

推荐用法：**电脑作为主库**（Chrome + 授权文件夹无感备份），手机只做临时录入，定期导出 JSON 回传电脑导入。

自动云同步（WebDAV/坚果云、Gist 等）技术上可行，但数据会经过第三方服务器，违背"绝对本地"理念，且有跨域与密钥风险，V1.x 阶段不做，列为 V3.0 以后再评估的可选项。

### 6.4 部署与 PWA 安装（已完成 · 2026-10-29）

**永久网址（GitHub Pages）**：

- 仓库：https://github.com/shuieryigoko-del/Inspiration-Inbox （每次改动都有提交历史，可看版本、可回滚）
- 应用：https://shuieryigoko-del.github.io/Inspiration-Inbox/ （自动跳转到 app/）
- 打开时需 VPN；**安装到主屏幕后日常使用完全离线、不需要 VPN**；仅更新版本时需开 VPN 刷新一次。
- 公开的只是空壳代码与文档，数据在各设备浏览器本地，任何人打开网址都看不到你的内容。

**三端"安装成 App"的方法（各做一次）**：

| 设备 | 浏览器 | 操作 |
|---|---|---|
| 电脑 | Chrome / Edge | 开 VPN 打开网址 → 地址栏右侧出现"安装"小图标（或菜单 → 安装此应用）→ 桌面与开始菜单出现图标，双击全屏运行 |
| iPhone / iPad | **必须用 Safari**（iOS 版 Chrome 不支持安装） | 开 VPN 用 Safari 打开网址 → 底部分享按钮 →「添加到主屏幕」→ 桌面出现图标 |
| 安卓 | Chrome | 开 VPN 打开网址 → 菜单 →「安装应用 / 添加到主屏幕」 |

安装后首次联网打开一次让 Service Worker 缓存完成，之后断网也能打开使用。iOS 注意：从主屏幕图标启动的 PWA 存储更持久；普通 Safari 标签页约 7 天不访问可能被系统清理。

**局域网临时试用（备用）**：电脑与手机连同一 Wi-Fi，电脑在 app 目录运行 `python -m http.server 8765 --bind 0.0.0.0`（允许防火墙弹窗），手机浏览器访问 `http://电脑IP:8765`（cmd 运行 ipconfig 查 IPv4 地址）。

**版本查看**：GitHub 仓库的 Commits 页面是每次改动的完整历史；重要版本会打 tag（如 v1.0），在 Releases/Tags 中可下载任意历史版本的完整代码包。
