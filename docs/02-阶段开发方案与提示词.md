## 二、Vibe Coding 工作守则（每次开发必读）

1. **单对话迭代**：不要分不同对话写不同板块。就在一个对话里完成到底，否则 AI 丢失上下文会导致变量名冲突、样式覆盖、白屏崩溃。
2. **一次一任务**：每次只让 AI 做一项，做完测试没问题，再做下一项。
3. **先骨架后皮囊**：先跑通核心功能，再调 UI。结构清晰时（CSS 都在 `<style>` 里），换肤只需一句"保留所有 JS 逻辑，只改 CSS"。
4. **报错不换对话**：遇到 BUG 直接把报错信息或截图发回同一对话。
5. **改完即备份**：每次可用版本导出一份 JSON 数据 + 把 index.html 复制到 backups/ 目录（命名加日期）。
6. **验收动作**：写完代码必须双击 index.html 用浏览器实际打开验证（断网也应可用）。
7. **发版走固定 SOP（v1.3 起固化为工作区技能 release-version）**：改四处版本号（顶栏文案、APP_VERSION、SW 注释、CACHE 名）→ `node --check` 语法校验 → 归档到 backups/code → commit → tag → push main 与 tag；代理不通时取消 git 本地代理直连。
8. **渲染层铁律不变**：新增任何用户内容的渲染，只用 createElement/textContent；URL 必须做协议白名单。

### 提示词 V1.0 · 框架与基础 UI（10.30 课上展示版，已完成）

> 用法：在 Trae 中新建对话，整段发送。要求 AI 把完整代码**直接写入 app/index.html 文件**（不要只在对话框输出）。

```
你是一个极其资深的纯前端工程师与 UI/UX 设计师。我们现在要开发一个名为「灵感收纳盒（Inspiration Inbox）」的 Web App。

【绝对死规定（每次写代码必须遵守）】
1. 技术栈：单文件 HTML（内联 CSS + 原生 Vanilla JS）。绝对禁止使用 React、Vue 或任何外部依赖库。代码必须双击即可在断网状态下运行。
2. 存储：使用浏览器原生 IndexedDB 进行数据持久化，绝对不使用 localStorage（因为要存图片）。数据不传服务器，保证绝对隐私。
3. 安全：渲染任何用户输入的文本时，必须使用 textContent 或作 HTML 转义，严禁直接使用 innerHTML，防止 XSS 注入。
4. 视觉（复古未来主义）：
   - 禁止使用直角和粗黑线。卡片、输入框、按钮使用微圆角（12px-16px）。
   - 带有柔和的阴影与毛玻璃效果（backdrop-filter: blur）。
   - 支持日/夜双模式切换，日间：银白/深灰字；夜间：深空灰/浅白字。（使用 CSS 变量控制）。
   - 日间：背景 #F5F5F7，卡片 #FFFFFF，文字 #1D1D1F。
   - 夜间：背景 #0F0F11，卡片 #1C1C1E，文字 #F2F2F7。
   - 字体：PingFang SC, Helvetica Neue, sans-serif；标题 font-weight: 600；正文轻盈；letter-spacing: 0.5px。

【数据结构定义（IndexedDB，库名 inspiration-inbox，表名 fragments，keyPath 为 id）】
每条素材包含字段：
id（时间戳）、space（'cold'/'workspace'/'core'）、type（'text'/'image'/'link'/'audio'）、
content（文本）、tags（数组）、image（Base64 字符串）、parentId（默认 null）、
audioUrl、coverImg、comments、createdAt（创建时间）。

【任务 1：框架与基础 UI（本次只做这些）】
1. 顶部栏（吸顶固定，毛玻璃）：左侧 Logo 文字"INSPIRATION"；中间药丸状实时搜索框（实时过滤文本与标签）；右侧日/夜切换按钮、导出数据按钮、导入数据按钮。
2. 三个 Tab：冷库、工作台、内核（点击后下方只展示对应 space 的数据；默认显示工作台）。
3. 录入区：极简 textarea（无边框）、标签输入框（可添加多个标签，如 #科幻 #音乐）、图片上传按钮（FileReader 转 Base64，建议 Canvas 压缩）、「封存碎片」胶囊主按钮。点击封存后写入 IndexedDB 并刷新瀑布流。录入区需带 space 归属选择（当前选中哪个 Tab 就存入哪个 space）。
4. 瀑布流展示区：使用 CSS columns 实现自适应瀑布流（电脑 3 列 / 平板 2 列 / 手机 1 列）。卡片展示文字、图片、标签、时间；Hover 轻微上浮并加深阴影。
5. 抽屉详情：点击卡片滑出详情抽屉——电脑端从右侧滑出（宽 40%），手机端从底部向上滑出（占屏 60%）。抽屉带毛玻璃背景、极致圆角、平滑动画（transition: transform 0.3s ease-out）。抽屉打开时不加全黑遮罩，背景瀑布流仍可上下滑动。抽屉内展示完整文本、大图、标签、时间。
6. 数据导入导出：导出——把 IndexedDB 全量数据打包为 JSON 下载；导入——选择 JSON 文件写入 IndexedDB 并刷新。
7. 响应式设计：完美适配电脑、iPad、手机。兼容性细节：毛玻璃效果需同时写 backdrop-filter 与 -webkit-backdrop-filter（Safari 需要）；File System Access API 必须先做特性检测（'showDirectoryPicker' in window）再启用，不支持时静默降级为普通下载，不得报错。
8. 自动备份与提醒（去重式，防冗余）：
   - 每次「封存」成功后，先对全量数据计算 hash（简单字符串散列即可），与 settings 表中的 lastBackupHash 比对：数据无变化则不备份，有变化才执行导出——从源头杜绝重复备份；
   - 浏览器支持 File System Access API（Chrome/Edge）时：首次提示用户授权一个备份文件夹，之后静默覆盖写入同一个 inspiration-backup-latest.json（始终只有一份、始终最新）；并每 7 天额外归档一份带日期的 inspiration-backup-YYYY-MM-DD.json，防止最新文件被误覆盖；
   - 浏览器不支持时（iPad Safari 等）：自动回退为普通下载，文件名固定 inspiration-backup-latest.json；
   - 顶部栏显示「距上次导出 X 天」的小字提醒，超过 3 天未导出时文字变红；
   - 上次导出时间、lastBackupHash、备份文件夹句柄（FileSystemDirectoryHandle 可直接存 IndexedDB）、日/夜主题等设置项，全部存入 IndexedDB 的 settings 表（keyPath 为 key），绝对不使用 localStorage。

请直接输出完整代码并写入 app/index.html 文件，不要用省略号省略任何部分，注释清晰，确保 iPad Safari 和电脑 Chrome 都能流畅运行。
```

### 提示词 V1.4 · 链接自动可点击（✅ 已完成 2026-10-30，提示词存档）

> 定位：纯渲染层小版本，不改数据结构、不改同步协议。实际实现与提示词一致，浏览器六项验收全过。

```
保留所有现有功能，只做增量修改，继续遵守单文件、textContent、断网可用全部铁律：

1. 在渲染层新增一个通用函数（如 render.linkedText(text, container)）：把文本中的 http:// 和
   https:// 链接识别出来，文本部分用 textContent 追加，链接部分用 createElement('a') 追加。
   绝对禁止用 innerHTML 拼接。
2. 链接 <a> 的要求：href 只允许 http/https 协议（识别到 javascript:、data: 等一律按纯文本
   显示，不可点击）；target="_blank"；rel="noopener noreferrer"；class 复用品牌强调色
   （var(--accent)，蓝色/紫色），可点击处加下划线；长 URL 在卡片中自动截断不撑破布局。
3. 卡片正文和抽屉详情正文都要使用这个函数，两处表现一致；搜索、导出、云同步、加密完全
   不受影响（content 原文一个字都不改）。
4. 验收：① 封存一条含 https://example.com 的碎片，卡片与抽屉里都能点，新标签页打开；
   ② 封存 javascript:alert(1)，页面必须纯文本显示、无脚本执行；③ 一条碎片里同时有
   普通文字、两个链接、中文，显示顺序正确；④ 手机/iPad 上点击不导致整卡片误触（链接点击
   不冒泡触发抽屉，stopPropagation）；⑤ 日夜模式下链接颜色都清晰；⑥ node --check 通过。
```

### 提示词 V1.4.4 · 同步可靠性加固（✅ 已完成 2026-10-31，提示词存档）

> 定位：不改数据结构、不改同步协议、不加新功能，只修三个隐患。真机现象：手机封存后 iPad/电脑点同步显示"无更新"，云端长时间未变。

```
在现有代码基础上只做可靠性修改，保留所有现有功能与铁律（单文件、textContent、断网可用）：
1. 自动同步失败不再静默：catch 里记录 lastError；手动同步照旧 toast；自动同步用 5 分钟内
   同一条错误只提示一次的节流 toast；同步按钮文字在失败后显示「☁ 待同步」，title 写明原因，
   下次成功自动恢复「☁ 云同步」。
2. 同步进行中又被触发时不要直接 return 'busy' 丢弃：置 _pending 标记（记住是否手动），
   在 finally 里若 _pending 为真则 400ms 后自动补跑一次。
3. 合并结果写库不要用 replaceAll（整库 clear + 重写，会把合并窗口内刚封存的新碎片冲掉）：
   新增 db.applyMerge(items, deadIds)，按 id put 全部合并结果，只 delete 墓碑中的 id。
4. 验收：① node --check 通过；② 断网时自动同步失败，按钮变「☁ 待同步」并有提示；
   ③ 恢复网络后点一次同步即成功、按钮恢复；④ 同步期间连续封存两条，最终三端都在。
```

### 提示词 V1.5 · 碎片可编辑（✅ 已完成 2026-10-31，v1.5.0）

> 现状：抽屉只能查看与删除，封存后无法改文字/标签/图片。数据无需迁移（updatedAt 已在）。

```
在已有代码基础上增加"编辑碎片"功能（保留所有现有功能，只做增量修改）：
1. 抽屉详情页顶部增加 [编辑] 按钮（与现有的展开/关闭同排），点击后进入编辑态。
2. 编辑态复用顶部录入区：把该碎片的 content 填入输入框，tags 填入标签区，图片放入预览区，
   录入区按钮文案变为「保存修改」，并显示一个「取消」。
3. 保存时：读取当前碎片对象，只覆盖 content / tags / image / imageW / imageH / type，
   updatedAt 设为 Date.now()，用 db 的 put 写回（新增 db.updateItem(item)），
   同步更新 state.items 中同 id 对象；关闭编辑态、重渲染、toast「已保存」、cloudSync.schedule()。
4. 图片：编辑态可以替换（重新压缩走 utils.compressImage）或删除（同时清 imageW/imageH）。
5. 取消编辑：录入区恢复空白初始态，不改任何数据。
6. 铁律：仍然 createElement + textContent；编辑不改 id、不改 createdAt；链接渲染沿用 linkedText。
7. 验收：① 改文字后卡片与抽屉立即更新；② 增删标签后搜索能命中新标签、旧的搜不到；
   ③ 换图后瀑布流不跨列跳动（依赖 imageW/imageH）；④ 同步后另两端看到的是修改后的版本；
   ⑤ node --check 通过；⑥ 手机窄屏编辑区可用、键盘不遮挡保存按钮。
```

### 提示词 V1.5.1 · 同步提速（索引与图片分离，待开工）

> 背景：同步文件 2026-10-31 已 1.48MB，手机单次同步要下载+上传整包，耗时数分钟。
> 目标：主文件回到几十 KB，只有改动过的图片才单独传一次。

```
在现有云同步层上改造存储布局（加密方式、LWW、墓碑、密码全部不变）：
1. Gist 内从"单一文件名"改为多文件：
   - inspiration-inbox-sync.json：只存碎片元数据（id/space/type/content/tags/createdAt/
     updatedAt/parentId 等），图片字段改为 imageRef（图片内容的 SHA-256 前 16 位十六进制）；
   - att-<imageRef>.json：单张图片的密文（信封结构与主文件相同，同一个 salt/密码派生）。
2. 拉取：主文件解密后，只对本地缺失的 imageRef 拉对应附件文件；已有的跳过。
3. 推送：只 PATCH 发生变化的文件（Gist 支持只更新 files 里指定的项）；删除碎片时，
   若某 imageRef 已无任何碎片引用，则把该附件文件设为 null 删除（孤儿附件清理）。
4. 兼容迁移：旧主文件里内嵌 image(base64) 的碎片，首次同步时自动抽出为附件并改写 imageRef，
   迁移后主文件不再含 base64。
5. 进度可见：同步按钮 title 或 toast 显示"上传 N 个附件 / 主文件 xx KB"。
6. 验收：① 新增一张图片 → 只新增一个附件文件 + 主文件更新，其余附件不动；
   ② 只改文字 → 只传主文件；③ 删除含图碎片 → 附件文件被清理，另两端不报错；
   ④ 三端图片都能正常显示；⑤ 弱网下同步耗时可感知下降；⑥ node --check 通过。
```

## 五、提示词迭代纪律（防翻车）

1. 每轮提示词开头加"**保留所有现有功能，只做增量修改**"。
2. AI 输出后先通读关键 JS 逻辑再运行；报错就把控制台红字原文发回。
3. 任何"顺手重构/换库/加框架"的提议一律拒绝——坚守单文件原生 JS。
4. 每完成一个任务，立即：导出 JSON 备份 → 复制 index.html 到 backups/（如 index-v1.0-20261029.html）。
5. **每次发版走 release-version SOP（四处版本号/语法校验/归档/提交/标签/推送），三端真机各点一次验证后再向用户宣布完成。**
6. 真机问题优先级：同一问题在两个以上真实设备复现 → 立即修并升小版本；只在模拟器出现 → 记录观察。
