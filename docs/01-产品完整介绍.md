# 灵感收纳盒 · 产品完整介绍（宪法）

> 版本：V1.5.0 | 更新日期：2026-10-31
> 本文档是产品的"宪法"。所有迭代提示词、代码、作业报告与本文件冲突时，以本文件为准。
> 一句话定义：**一个绝对本地、多模态、可以被"翻找"的精神档案库——本地优先，云端可选且只有密文。**

---

## 一、产品定位

灵感收纳盒是一个**纯前端单文件网页应用**（一个 `index.html`，双击即用，免费，不上架），用来安放人在信息洪流中转瞬即逝的灵感碎片：一句话、一张图、一个链接、一段声音（音频为后续版本的外链引用形态）。

它不是笔记 App，不是网盘，不是待办清单。它是一个有三层空间的"盒子"：

- **冷库（Cold）**：未经整理的原始素材，先扔进来，不评判。
- **工作台（Workspace）**：正在被加工的灵感，可以整理、关联（V2.0）。
- **内核（Core）**：最终沉淀下来的、属于个人精神内核的成品片段。

核心理念的演进（2026-10-30 定稿）：

1. **数据主权优先**：数据主体永远存放在用户自己设备上，应用不强制注册、不依赖任何必须在线的业务服务器。
2. **从"物理隔离"到"密码学隔离"**：V1.0 曾坚持"数据绝不上云"；三端真实使用后，我们把它升级为——**云端只允许存在密文，密钥只在用户手里**。用户选择开启云同步后，GitHub 服务器上保存的是 AES-256 加密后的乱码，应用作者、GitHub、任何旁观者都无法阅读。这与 Standard Notes、Joplin 等零知识（zero-knowledge）产品是同一种信任模型。
3. **本地优先（local-first）始终不变**：断网时所有记录功能完整可用，同步只是"后台信箱"；关闭同步、删光云端，应用照常运行。

## 二、产品哲学（为什么不是又一个笔记 App）

1. **多模态优先于文字**：灵感的载体常常不是文字。支持文本、图片，链接在 V1.4 计划自动识别为可点击；音频走"外链引用"（V2.1）。
2. **先收纳，后整理**：不强迫分类、不强迫标题、不强迫当场写长文。
3. **空间隐喻优于文件夹**：冷库/工作台/内核是状态流转，不是目录嵌套。
4. **可翻找优于强整理**：搜索、标签、时间排序、（V2.0 的）父子关联，都是为了"回头找得到"。
5. **零负担**：无登录、无加载等待、无红点、无社交、无算法推荐。
6. **克制是高级功能**：刻意不做文档树、不做多人协作、不做重型编辑器。

## 三、功能定义

### 3.1 碎片的类型（Fragment）

| 类型 | 内容形态 | 状态 |
|---|---|---|
| text | 纯文字，长短不限 | ✅ |
| image | 图片，浏览器端 Canvas 压缩（最长边 1280px、JPEG 0.82）后存 IndexedDB | ✅ |
| link | 链接 | ✅ 可粘贴 URL 存入；**V1.4 起正文中的 http/https 链接自动渲染为品牌色可点击链接**（卡片与抽屉一致，协议白名单防注入）；🔜 V2.x 独立链接卡片（标题/封面/描述，零后端下本地解析+优雅降级） |
| audio | 音频 | 🔜 V2.1 仅外链引用（audioUrl），禁止上传 MP3 |

每条碎片的固定字段：`id`、`space`、`type`、`content`、`tags[]`、`image`、`createdAt`、`updatedAt`、`parentId`（V2.0 启用）、墓碑删除记录（同步用）。

### 3.2 空间流转

碎片默认可在三个空间之间移动；工作台是使用最频繁的区域。碎片以瀑布流呈现，按创建时间倒序；支持标签筛选与全文搜索。

> 技术说明：瀑布流为 **flex 分列 + JS 按最矮列分发**（V1.3.4 起，替代在 iOS Safari 上会渲染白块的 CSS 多列布局）；V1.4.1 起图片卡按压缩时记录的宽高用 `aspect-ratio` 预留高度，**卡片入列后不再移动**，消除图片解码后"飞到别的列又回来"的闪烁。
>
> **抽屉与背景的关系（V1.4.3 定型）**：详情抽屉在电脑/平板从右侧滑出（40% 宽），顶栏与瀑布流同步向右让出等宽空间，卡片不会被遮住、背景仍可滚动；手机端为底部抽屉**两档形态**——默认半屏 44vh（背后碎片流仍可大面积浏览，点顶部抓条/˄ 展到 92vh 看长内容，再点收回），每次打开重置为半屏，长文在抽屉内部独立滚动；列表底部留白随档位变化。刻意不做小红书式双列——长文字卡片在双列下阅读拥挤，单列更符合"文字+图片混合"的内容形态。

### 3.3 标签

每条碎片可挂多个标签；标签只做检索入口，不做层级。输入时空格、逗号、顿号、`#` 均可分隔——`#A#B#C` 连写也会自动拆成三个标签（V1.4.1）。

### 3.4 搜索（V1.0 已实现 / V2.0 增强）

V1.0：文本与标签的实时模糊搜索。
V2.0：搜索结果**穿透父素材**——命中的子素材连同其父卡片一起出现。

### 3.5 备份与云同步（V1.0–V1.3 完成）

本地备份三重保险：① 变更 hash 去重；② Chrome/Edge 授权文件夹静默覆盖写 `latest.json` + 7 天归档；③ 触屏/iOS 走系统分享面板导出；外加普通下载回退。导入按钮常驻，支持灾难恢复。
**未授权文件夹时，封存后不弹任何保存框、不自动下载**（V1.4.1 起所有平台一致），避免"每存一条弹一次另存为/下载目录堆积文件"；安全网由顶部"X 天未备份"红字提醒、手动「导出备份」与云同步共同承担。

**三端云同步（V1.3 起可选开启，V1.3.5 打磨完成）**：

- 通道：GitHub Gist（秘密 Gist，不公开）；零自有服务器。
- 加密：PBKDF2 派生（15 万次）+ AES-256-GCM 端到端加密；信封 `{v:1,salt,iv,ct}`，版本字段为未来升级算法预留。
- 合并：按 `id` + 最后修改时间 LWW（新者胜）；删除用 30 天墓碑同步，不会在别的设备复活。
- 自动时机：启动 1.5 秒、本机改动后 5 秒防抖、回前台/获焦/pageshow 约 1.2 秒、页面可见时每 45 秒轮询、恢复联网后补传。
- 请求禁用缓存（`cache:no-store`），保证轮询拿到的是最新云端数据。
- **轻量轮询（V1.4.2）**：同步文件随图片积累接近 1MB 后，"每轮全量下载+全量上传"在慢网络下会像卡住。现改为：① 拉取带 ETag 条件请求，云端未变只回 304（几百字节），免下载/解密/合并；② 本地状态指纹与上次推送一致则跳过全量上传，只有真正发生改动的设备才写 Gist。
- 第二台设备免填 Gist 编号，令牌+密码后自动发现。
- 同步密码不可找回（零知识架构的必然属性，与 Joplin/Standard Notes 一致），界面已显著提示。

### 3.6 父子关联（V2.0，未做，下一步主线）

碎片之间可建立"父—子"关系，只加一层，不做无限层级。交互约束（防止回到"文件夹整理地狱"）：

1. 只能在工作台空间操作；2. 只能"抽屉内多选勾选关联"，禁止拖拽；3. 子素材可以"推入导航"；4. 可随时"剥离"；5. 搜索穿透；6. 提供"上帝视角"总览开关。

> 数据库字段 `parentId` 与索引在 V1.0 就已建好，**V2.0 无需数据库迁移**，这是刻意预留的扩展条件。

### 3.7 安装与离线（PWA，V1.2 完成，原 V3.0 愿景提前实现）

- 永久网址（GitHub Pages）：https://shuieryigoko-del.github.io/Inspiration-Inbox/
- `manifest.webmanifest` + `service worker`：安装后主屏幕出现「灵」字图标，全屏独立运行，断网可开可用。
- 更新策略：HTML 网络优先、静态资源缓存优先；新版本就绪后出现"🔄 发现新版本，点此立即更新"提示，避免用户卡在旧缓存。
- iOS 上只有 Safari 能添加主屏幕（Edge/Chrome 被系统限制）；主屏幕 App 与浏览器标签页是两个独立数据容器，需用云同步或导出/导入搬家。
- 应用内「📲安装App」按钮对 iOS/安卓/容器环境给出图文手动指引（V1.3.1–V1.3.3 三版打磨）。

### 3.8 主题与视觉（V1.0 已定调并严格落地）

复古未来主义：大留白、细描边、极轻毛玻璃、弱阴影；日/夜双模式。V1.3.5 代码色值与 V1.0 提示词逐字对账一致：

| 角色 | 日 | 夜 |
|---|---|---|
| 背景 | #F5F5F7 | #0F0F11 |
| 卡片 | #FFFFFF | #1C1C1E |
| 主文字 | #1D1D1F | #F2F2F7 |
| 品牌强调 | #5E5CE6（日）/ #7D7BFF（夜），仅用于主按钮与链接 | |
| 字体 | PingFang SC / Helvetica Neue（Windows 回退微软雅黑）；标题 600 字重、字距 0.5px | |
| 圆角 | 12–16px；毛玻璃含 -webkit 前缀 | |

### 3.9 安全铁律（任何版本不可违背）

1. 所有用户内容一律 `textContent` / `createElement` 渲染，禁止 `innerHTML` 插入用户数据；
2. 外链仅允许 http/https 协议（V1.4 链接功能的硬约束，杜绝 `javascript:` 注入），新标签打开且带 `rel="noopener noreferrer"`；
3. 不收集任何用户信息；令牌仅存本机 IndexedDB；
4. XSS 自测（输入 `<script>alert(1)</script>`）必须永远通过。

## 四、目标用户与场景

文科生、研究者、创作者、任何"想法很多但懒得整理"的人。典型场景：

- 地铁上突然想到一句话 → 手机扔进冷库；
- 看到一张图/一个链接 → 粘贴/分享进盒；
- 周末翻找，把相关碎片拖进工作台，关联、补充（V2.0）；
- 最终把打磨好的片段移入内核；V2.5 内核支持 Markdown 导出。

三端真实使用画像（已实现）：Windows 电脑（主库，Chrome/Edge）、iPad（Safari 主屏幕 App）、华为鸿蒙手机（华为浏览器/出境易 Edge），三端通过端到端加密云同步保持一致。

### 5.3 在同类产品中的坐标

flomo（碎片记录）、Cubox（稍后读收藏）、Karakeep/memos（开源自建）解决"收集"；Joplin、Standard Notes、Notesnook、Anytype 解决"加密同步"。灵感收纳盒的独特组合是：**零后端、零注册、单文件、端到端加密 + 三空间精神档案隐喻**，且为文科生可理解、可独立维护的规模。调研全文与可借鉴点见 [07-实践二提交方案](07-实践二提交方案.md) 附录。

## 六、非目标（明确不做）

- 重型富文本/Markdown 编辑器（内核导出除外）；
- 多人实时协作、评论、社交、Feed；
- 文件夹/文档树；
- 自建账号体系、自建同步服务器（Gist 是"借来的哑存储"）；
- 音视频本地上传与媒体库；
- 忘记密码可找回（零知识架构下技术上不成立）。
