## 二、功能清单（现场演示动线）

1. 三空间 Tab：冷库 / 工作台 / 内核，碎片按空间隔离；
2. 多模态封存：文字、标签、图片（本地 Canvas 自动压缩）；
3. 瀑布流卡片 + 实时搜索（文本与标签）+ 标签筛选；
4. 点击卡片滑出沉浸式抽屉详情，背景瀑布流不遮罩、可继续滚动；
5. 日/夜双模式（复古未来主义视觉，刷新后保留选择）；
6. 数据安全：一键 JSON 导出/导入；自动备份（电脑静默写文件夹，iPad/手机走系统分享，hash 去重）；
7. PWA：安装为桌面/主屏幕全屏应用，**断网可开可用**；
8. ☁ 三端云同步（可选开启）：GitHub Gist 密文存储、AES-256 端到端加密、三端自动双向合并；
9. XSS 防护：输入 `<script>alert(1)</script>` 原样显示，不执行。

## 四、核心叙事：从"绝对本地"到"本地优先 + 零知识云同步"（本方案的灵魂章节）

### 4.1 最初的设想

实践一方案里，产品被定义为"绝对本地的多模态精神档案库"：纯前端、IndexedDB、数据绝不上传服务器。这个选择出于两个真实痛感：① 灵感内容高度私密，不信任云端公司；② 文科生也能完全掌控、双击即用。

### 4.2 真实使用把矛盾逼了出来

v1.2 把应用装到自己的电脑、iPad、手机后，"绝对本地"的代价立刻显形：**三台设备三个互不相通的数据库**。手机上随手记的灵感，回到电脑前看不见；每次要靠手动导出/导入 JSON 搬运。"安全"与"可用"在多设备时代成了对立面。

### 4.3 关键认知：隐私的敌人不是"云"，是"被人看见"

调研后我意识到，商业笔记产品（flomo、Cubox 等）的云端是**明文**的——公司能读、泄露即裸奔；而一类成熟开源产品（Joplin、Standard Notes、Notesnook）给出了另一条路：**零知识架构（zero-knowledge）**——服务器只存密文，密钥从用户口令在本机派生，服务提供者在数学上无法阅读内容。

于是理念从"物理隔离"升级为"密码学隔离"，但保留三条不可退让的底线：

1. **本地优先（local-first）**：本地数据库永远是主体，断网时全部记录功能照常工作，同步只是"后台信箱"；
2. **云端只见密文**：GitHub Gist 作为借来的"哑存储"，保存的是 `{salt, iv, ct}` 加密信封；
3. **可退出**：随时能吊销令牌、删除 Gist、导出全部数据为 JSON，不被任何平台锁定。

### 4.4 怎么实现的（文科生也能讲清的技术点）

- 用"同步密码"通过 **PBKDF2 算法迭代 15 万次**派生出加密密钥（与 Joplin 新版的加密选型同族；迭代次数让暴力破解成本极高）；
- 数据用 **AES-256-GCM** 加密（自带防篡改校验），每次随机向量 IV，结果 Base64 后存入一个秘密 Gist；
- 三端合并：每条碎片有唯一 id 和最后修改时间，"新者胜"（LWW，与开源笔记 TriliumNext 的成熟做法一致）；删除靠"墓碑"标记传播，30 天有效，被删的内容不会在别的设备复活；
- 密码不可找回——这不是缺陷，而是零知识的证明：连系统设计者都无法打开，才是真加密。

### 4.5 这件事教会我什么

- **方案是用出来的，不是规划出来的**：三端割裂、Safari 白块、电脑同步慢，没有一个是坐在书桌前能预见的；
- **价值观要靠工程能力守住**："重视隐私"谁都会说，真正的取舍是去理解密钥派生、冲突合并这些枯燥机制；
- **AI 协作中人类负责"该不该"**：AI 能实现任意方案，但"要不要上云、什么是不能让渡的底线"，只能由产品主人回答。

## 五、工程要点（老师可能追问的技术问题备答）

1. **为什么不用 React/Vue？** 单文件、双击即开、断网可用是硬约束；应用规模原生 JS 足够，框架只增加构建链负担。
2. **代码怎么管得住复杂度？** 六层架构（工具/数据库/云同步/状态/渲染/事件/启动）严格单向依赖，1760+ 行仍可维护。
3. **为什么不用 localStorage？** 要存图片（Base64，体积大），IndexedDB 才支持大容量结构化存储。
4. **PWA 更新怎么保证用户不卡旧版？** HTML 网络优先、静态资源缓存优先，新 SW 就绪弹"发现新版本"提示。
5. **同步冲突怎么办？** LWW + 墓碑；唯一边界是同一条碎片两设备断网同时编辑，保留较新版本（概率极低，已在文档说明）。
6. **安全做了什么？** 所有用户内容只用 textContent/createElement 渲染（全站无 innerHTML 注入点）；V1.4 计划的链接功能也限定 http/https 协议白名单；令牌仅授予 gist 单一权限、可随时吊销。
7. **加密参数会过时吗？** 密文信封带版本号 v:1，未来可平滑升级算法。

**对本项目的借鉴结论**：

1. 加密选型得到印证：AES-GCM + PBKDF2 与 Joplin 同族，密钥信封版本化与 Standard Notes 的协议版本思路一致；暂不需要 Argon2id（需引入 WASM）；
2. 合并策略得到印证：LWW + 墓碑是成熟开源产品验证过的轻量方案；CRDT（Yjs/Automerge、Anytype 路线）对短碎片场景过重，列为远期观察项；
3. 可继续低成本借鉴：导出即卖点（flomo/Readwise 都把多格式导出做深）；Gist 单文件体积变大后，可把索引/附件/墓碑拆成多文件降低写放大（Joplin item 协议思路）；
4. 明确不学：自建全家桶服务器（Notesnook 需多个微服务、Karakeep 需 headless Chrome 抓取）、AI 自动打标、多人协作；链接预览（OG 抓取）在零后端下受 CORS 限制，V2.x 只能"本地解析 + 优雅降级"；
5. 产品坐标：商业产品强在体验但明文云端，开源加密产品强在安全但部署重——灵感收纳盒的位置是"**零后端、零注册、单文件、文科生可独立维护**的零知识碎片盒"。
