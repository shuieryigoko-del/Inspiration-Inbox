## 第一部分：数据结构（IndexedDB 表结构）

### 1.1 数据库基本信息

| 项目 | 值 | 说明 |
|---|---|---|
| 数据库名 | `inspiration-inbox` | 全项目唯一 |
| 主表（ObjectStore） | `fragments` | 所有碎片/素材都存这一张表，keyPath 为 `id` |
| 设置表（ObjectStore） | `settings` | 存应用设置（日/夜主题、上次导出时间等），keyPath 为 `key`，只有几条记录 |
| 版本号 | 1 | 升级结构时才递增 |

**为什么素材只用一张表？** 三层空间（冷库/工作台/内核）用 `space` 字段区分即可，查询时按 space 过滤。单表简单、不易乱，V1.0 阶段绝对够用。

**为什么另设 settings 表？** 项目死规定禁用 localStorage，而"日/夜主题选择""上次导出时间"这类小设置也需要持久化，所以开一个极简的键值对表：

| key | value 示例 | 说明 |
|---|---|---|
| `theme` | `'light'` / `'dark'` | 日/夜模式，启动时读取 |
| `lastExportAt` | `1761800000000` | 上次导出时间戳，用于"距上次导出 X 天"提醒 |
| `lastBackupHash` | `'a3f9c2...'` | 上次备份数据的 hash，用于变更检测：数据没变就不重复备份 |
| `lastArchiveAt` | `1761800000000` | 上次归档时间戳，用于"每 7 天归档一份带日期备份" |
| `backupDirHandle` | FileSystemDirectoryHandle | Chrome/Edge 授权的备份文件夹句柄（句柄可以直接存 IndexedDB），实现静默覆盖写入 latest.json |

### 1.2 字段定义（全量版）

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `id` | number | 是 | `Date.now()` | 时间戳主键，创建时生成 |
| `space` | string | 是 | `'workspace'` | 空间归属：`'cold'` 冷库 / `'workspace'` 工作台 / `'core'` 内核 |
| `type` | string | 是 | `'text'` | 素材类型：`'text'` / `'image'` / `'link'` / `'audio'` |
| `content` | string | 是 | `''` | 正文内容（灵感文字/通感评论） |
| `tags` | array | 否 | `[]` | 标签数组，如 `["科幻","待用"]` |
| `image` | string | 否 | `null` | 图片的 Base64 字符串（Canvas 压缩后） |
| `parentId` | number/null | 否 | `null` | 父级 id。null = 独立卡片；有值 = 被折叠进父级 |
| `audioUrl` | string | 否 | `null` | 音频直链（V2.1 音乐卡用，V1.0 先留字段） |
| `coverImg` | string | 否 | `null` | 封面图 URL（同上） |
| `comments` | string | 否 | `''` | 随想备注（同上） |
| `createdAt` | number | 是 | `Date.now()` | 创建时间戳，用于排序 |

### 1.3 V1.0 必须优先跑通的最小字段集

> 第一版写代码时，**只要这 8 个字段全部落库成功，V1.0 的地基就算打好了**。其余字段（audioUrl/coverImg/comments）先在数据结构里留好位置，阶段 3 才启用。

```
id · space · type · content · tags · image · parentId · createdAt
```

### 1.4 索引设计（让检索够快）

| 索引名 | 字段 | 用途 |
|---|---|---|
| `space` | space | Tab 切换时快速取某一空间的全部卡片 |
| `parentId` | parentId | 查询某卡片的所有子素材；主视图筛掉被折叠卡片 |
| `createdAt` | createdAt | 按时间倒序排列瀑布流 |

> tags 和 content 不建索引——V1.0 数据量小，搜索直接在内存里遍历过滤即可，简单可靠。

### 1.5 一条数据示例

```json
{
  "id": 1761800000000,
  "space": "workspace",
  "type": "image",
  "content": "赛博朋克配色的雨夜街景，霓虹倒映在积水里",
  "tags": ["赛博朋克", "色彩", "待用"],
  "image": "data:image/jpeg;base64,/9j/4AAQ...",
  "parentId": null,
  "audioUrl": null,
  "coverImg": null,
  "comments": "",
  "createdAt": 1761800000000
}
```

### 1.6 数据铁律（写进代码注释里）

1. **关联 ≠ 删除**：任何素材无论是否被关联，底层记录永远独立存在，关联只是给记录加 `parentId`。
2. **搜索穿透**：搜索不过滤 `parentId`，被折叠素材命中时必须显示并标注父级。
3. **导出即全量**：导出 JSON 必须包含所有记录（含被折叠的），一条不落。

## 第二部分：单文件代码分层结构

> 虽然是单文件 HTML，但 `<script>` 内部必须按"层"组织代码，每层之间用注释横幅隔开。这样代码写到几千行也不会乱。

### 2.1 文件总体结构

```
index.html
├── <head>
│   └── <style>  ………………………  第 0 层：样式层（CSS 变量 + 全部样式）
├── <body>
│   └── HTML 骨架  ……………………  顶部栏 / Tab栏 / 录入区 / 瀑布流容器 / 抽屉
│   └── <script>
│       ├── 第 1 层：常量与工具层（utils）
│       ├── 第 2 层：数据操作层（db）
│       ├── 第 3 层：状态层（state）
│       ├── 第 4 层：UI 渲染层（render）
│       ├── 第 5 层：事件监听层（events）
│       └── 第 6 层：启动入口（init）
```

### 2.2 各层职责与包含的函数

#### 第 0 层：样式层（`<style>` 内）
- `:root` 与 `[data-theme="dark"]` 两套 CSS 变量（颜色、阴影、圆角）
- 布局样式：顶部栏（毛玻璃吸顶）、Tab 栏、录入区、瀑布流（columns）、卡片、抽屉（transform 滑入滑出）
- 响应式媒体查询（电脑 3 列 / 平板 2 列 / 手机 1 列；抽屉宽度切换）
- 铁律：所有圆角 12-16px；无直角无粗黑边；主题切换用变量瞬切

#### 第 1 层：常量与工具层（utils）
```
escapeHTML(str)      —— 转义用户输入，防 XSS（或统一用 textContent）
compressImage(file)  —— Canvas 压缩图片，返回 Promise<Base64>
downloadFile(name, content, type) —— 触发浏览器下载（导出 JSON/MD 用）
formatTime(ts)       —— 时间戳转可读日期
```
职责：纯函数，不碰页面、不碰数据库，给上层调用。

#### 第 2 层：数据操作层（db）
```
openDB()        —— 打开/创建 IndexedDB（库 inspiration-inbox，表 fragments，建 3 个索引）
addItem(item)   —— 新增一条素材
getAll()        —— 读取全部素材
updateItem(item)—— 更新（改 parentId、改内容都用它）
deleteItem(id)  —— 删除
clearAndImport(list) —— 导入 JSON 时批量写入
```
职责：**全项目只有这一层允许碰 IndexedDB**。上层想要数据，只能调用这里的函数。这样以后改存储方式只改这一层。

#### 第 3 层：状态层（state）
```
state = {
  currentSpace: 'workspace',  // 当前选中的 Tab
  searchText: '',             // 搜索框内容
  showAllLinked: false,       // 上帝视角开关（V2.1 启用）
  theme: 'light',             // 日/夜模式
  items: []                   // 内存中的全量数据缓存
}
```
职责：记住"界面现在处于什么状态"。渲染层只根据 state 决定画什么。

#### 第 4 层：UI 渲染层（render）
```
renderAll()          —— 总入口：根据 state 重新渲染（数据/状态变了就调它）
renderCards(list)    —— 把卡片列表画进瀑布流（用 textContent 赋值！）
renderDrawer(item)   —— 填充抽屉详情内容
openDrawer()/closeDrawer() —— 抽屉滑入滑出
applyTheme()         —— 按 state.theme 切换 CSS 变量
```
职责：只负责"画"。数据从 state 拿，不直接碰 IndexedDB。

#### 第 5 层：事件监听层（events）
```
bindEvents() —— 统一绑定所有交互：
  · 封存按钮点击 → 收集表单 → db.addItem → 刷新 state → renderAll
  · 搜索框输入 → 更新 state.searchText → renderAll
  · Tab 点击 → 更新 state.currentSpace → renderAll
  · 卡片点击 → openDrawer + renderDrawer
  · 日/夜按钮 → 切 state.theme → applyTheme
  · 导出按钮 → db.getAll → downloadFile
  · 导入按钮 → 读文件 → db.clearAndImport → renderAll
```
职责：用户操作的唯一入口，把"操作 → 改数据 → 改状态 → 重绘"串起来。

#### 第 6 层：启动入口（init）
```
init() —— 页面加载后执行：openDB → 读全量数据进 state → applyTheme → bindEvents → renderAll
```

### 2.3 数据流向图（一句话记住）

```
用户操作(events) → 改数据(db) → 更新状态(state) → 重新渲染(render) → 用户看到结果
单向流动，绝不逆行（render 永远不直接改数据）。
```

## 第三部分：从零搭建的 8 个步骤

> 每一步都是"能立刻看到效果"的最小动作。每步完成就在浏览器里验证，通过后再做下一步。这也是给 AI 下指令的顺序。

| 步骤 | 做什么 | 验收方法（双击打开 index.html） |
|---|---|---|
| **第 1 步** | 写 HTML 骨架 + 样式层：顶部栏、Tab 栏、录入区、空的瀑布流容器、隐藏的抽屉；CSS 变量定义日/夜两套主题 | 页面有完整布局，点日/夜按钮颜色能切换（此时按钮逻辑可用 5 行临时代码），手机上看不变形 |
| **第 2 步** | 写数据操作层：openDB + addItem + getAll，并在控制台测试 | 控制台执行 addItem/getAll 不报错；DevTools → Application → IndexedDB 里能看到 inspiration-inbox 库和 fragments 表 |
| **第 3 步** | 打通录入：封存按钮 → 收集 textarea/标签/图片 → addItem | 填内容点封存，IndexedDB 里多出一条记录（图片转成了 Base64） |
| **第 4 步** | 写渲染层：init 时 getAll → renderCards 画瀑布流 | 刷新页面，刚存的卡片出现在瀑布流；文字用 textContent 渲染 |
| **第 5 步** | 加搜索过滤 + Tab 切换（state 层正式上岗） | 输入关键词卡片实时减少；切 Tab 只显示对应 space 的卡片 |
| **第 6 步** | 做抽屉：点卡片滑出详情，带滑入动画，背景可滚动 | 电脑右侧滑出（40% 宽），手机底部滑出（60% 高），无全黑遮罩 |
| **第 7 步** | 加导入导出：导出 JSON 下载；导入 JSON 恢复数据 | 导出文件可下载；删掉数据后导入能完整恢复 |
| **第 8 步** | 整体打磨：日/夜切换持久化、XSS 自检、三端响应式检查 | 控制台无报错；输入 `<script>` 不执行；手机/平板/电脑布局正常 |

**完成第 8 步 = V1.0 课堂展示版完成。** 之后按《02-阶段开发方案与提示词》进入任务 2。

### 防乱纪律

1. 新函数先想清楚属于哪一层，写进对应注释横幅下面，**不许插队**。
2. 任何层不许跨层操作：render 不碰 db，events 不直接画 DOM（必须走 render）。
3. 每次让 AI 改代码，提示词里都带上："请保持现有的六层代码结构，新代码写入对应分层"。
