# 灵感收纳盒 · 技术架构指南（V1.4.4）

> 更新日期：2026-10-31 | 对应代码：`app/index.html`（1970 行，单文件）+ `app/sw.js` + `app/manifest.webmanifest`
> 阅读对象：文科背景的产品本人，以及协助开发的 AI。原则：**先讲为什么，再讲怎么做。**

---

## 一、技术选型一句话

**一个 `index.html` = 全部应用**：内联 CSS、原生 Vanilla JS、零外部依赖、零框架；数据存浏览器内置的 IndexedDB；网页本身可被 Service Worker 缓存实现离线；云同步借用 GitHub Gist 作为"哑存储"，内容端到端加密。

为什么不用 React/Vue：单文件、双击即开、断网可用是硬约束；本应用的交互复杂度原生 JS 完全够用，框架只会带来构建链与维护负担。

---

## 二、代码分层（index.html 内六层 + 同步层）

代码按注释横幅分层，**依赖只能从上往下，不允许反向引用**：

```
第 0 层  样式层      <style>：CSS 变量日夜主题、全部组件样式
第 1 层  常量与工具  const 常量、hash、时间格式化等纯函数，不碰页面和数据库
第 2 层  数据层 db    全项目唯一允许操作 IndexedDB 的地方（CRUD、设置项、导入导出）
第 2B 层 云同步 cloudSync  本地优先的可选服务（加密、Gist 通信、合并、墓碑）
第 3 层  状态层 state 当前界面状态（当前空间、搜索词、待存图片等），渲染只认它
第 4 层  渲染层 render 只负责"画"，不直接改数据库
第 5 层  事件层 events 用户操作 → 改数据 → 更新 state → 重绘
第 6 层  启动层 init  开库、绑定、首次渲染、安排启动后同步
（旁路） setupPWA()  Service Worker 注册、更新提示、安装按钮引导
```

**为什么必须分层**：Vibe Coding 最常见的死法是 AI 多轮迭代后把数据库调用、DOM 操作、业务判断搅成一团，下一轮任何修改都引发连锁白屏。分层后 AI 每轮只需遵守"在哪层改哪层"，1700+ 行仍然可维护。

整洁度体检（2026-10-30，V1.4）：全文件 **0 处 TODO/FIXME**；横幅与层级齐全（顶部横幅已更新为 v1.4 并列明 2B 层与外链铁律）；无挂起技术债。

## 三、数据层设计（IndexedDB）

- 库名：`inspiration-inbox`，`DB_VERSION = 1`（V1.0 至今未升级——所有扩展都靠"加字段不删字段"兼容，无需 onupgradeneeded 迁移）。
- 对象仓库：

| 仓库 | keyPath | 索引 | 存什么 |
|---|---|---|---|
| `fragments` | `id` | `space`、`parentId`、`createdAt` | 全部碎片 |
| `settings` | `key` | 无 | 全部键值设置 |

### fragments 字段（V1.4.1 实际）

| 字段 | 含义 | 加入版本 |
|---|---|---|
| `id` | Date.now()+随机数，全局唯一 | V1.0 |
| `space` | cold / workspace / core | V1.0 |
| `type` | text / image / link / audio（link、audio 预留） | V1.0 |
| `content` | 文本原文 | V1.0 |
| `tags` | 字符串数组 | V1.0 |
| `image` | Canvas 压缩后的 Base64（最长边 1280，JPEG 0.82） | V1.0 |
| `parentId` | 父碎片 id，默认 null；**V2.0 直接启用，无需迁移** | V1.0 预留 |
| `audioUrl` / `coverImg` / `comments` | V2.1 音乐卡预留 | V1.0 |
| `createdAt` | 创建时间戳 | V1.0 |
| `updatedAt` | 最后修改时间戳，**云同步 LWW 合并的判据**；关联/剥离也要更新它 | V1.3 |
| `imageW` / `imageH` | 压缩后图片宽高，渲染时 aspect-ratio 占位防跳动；旧数据缺省时图片解码后补算 | V1.4.1 |

### settings 键（实际）

`theme`、`lastExportAt`、`lastBackupHash`（djb2 指纹，去重备份）、`lastArchiveAt`、`backupDirHandle`（FS Access 文件夹句柄，可直接结构化克隆入库）、`syncToken`、`syncPassword`、`syncGistId`、`syncSalt`、`tombstones`（`[{id,at}]`，保留 30 天）、`lastSyncAt`、`syncEtag`（V1.4.2，云端 Gist 响应的 ETag，条件请求用）、`syncStateHash`（V1.4.2，上次成功推送的整体状态指纹）。

> 安全说明：同步密码存 IndexedDB 仅为本机免重复输入，它从不出现在明文明文通信里；云端只存加盐哈希派生后的密文。彻底不用同步时点「取消本机同步配置」即可清除。

## 四、备份模块（backup.run）

返回值：`unchanged / dir / shared / download / skipped / cancelled`，调用方据此提示。

三策略 + 特性检测：
1. 授权文件夹（Chrome/Edge 且 pointer:fine）：覆盖写 latest.json + 7 天归档；
2. 触屏/iOS：`navigator.share` 系统分享（存储到"文件"/微信），取消不产生垃圾文件；
3. 普通下载回退。
所有路径前置 hash 去重；导入为全量合并式写入，不覆盖未涉及记录。

**自动模式的打扰边界（V1.4.1）**：封存触发的自动备份在**未授权文件夹时一律返回 `skipped`，不下载、不弹窗**——Edge/Chrome 若开启"下载前询问保存位置"，旧逻辑会每封存一条弹一次另存为，静默下载也会让下载目录堆满文件。安全网改为：顶栏"X 天未备份"红字提醒、手动「导出备份」、云同步三重。

## 五、云同步层（第 2B 层，V1.3 新增，V1.3.5 定型）

### 5.1 信任模型

**零知识（zero-knowledge）**：GitHub 账号下建一个秘密 Gist（public:false），文件名 `inspiration-inbox-sync.json`。服务器上只有密文；密钥由"同步密码"经 PBKDF2 在本机派生，任何人（含应用作者、GitHub）都无法阅读。令牌仅授予 gist 单一权限。

### 5.2 加密方案（Web Crypto API，零第三方库）

- 密钥派生：`PBKDF2`（SHA-256，**150000 次迭代**，随机 16 字节盐）→ `AES-GCM` 256 位密钥；
- 加密：AES-GCM（自带完整性校验，密文被改动会解密失败），随机 12 字节 IV；
- 信封：`{v:1, salt, iv, ct}`（均 base64）。**`v:1` 是版本号**，未来升级算法（如 Argon2id）时可按版本兼容——这是刻意预留的升级条件；
- 盐以云端信封为准，新设备第一次拉取即取得同盐，保证同一密码派生出同一密钥；
- 自测：`cloudSync.selftest()` 挂在 window，验证 cryptoOk / wrongPasswordRejected / mergeOk（开发排错用）。

> 横向参照（2026-10 调研）：Joplin 的新版端到端加密同为 AES-256-GCM + PBKDF2（22 万次，对齐 OWASP）；我们的 15 万次同处安全量级。Standard Notes/Notesnook 用 XChaCha20-Poly1305 + Argon2id，更强但需引入 WASM，课程项目无需过度设计。

### 5.3 同步协议（无状态、单文件，V1.4.2 起条件化）

1. 拉：`GET /gists/{id}`，带 `If-None-Match: <syncEtag>`（第二台设备先 `_findGist()` 在自己的 gist 列表里按文件名自动发现，免填 id）；
   - 云端未变 → **304**（几百字节），直接跳过下载、解密、合并与库重写；
   - 有变化 → 200，保存新 ETag，解密 → `_merge()`：按 id 合并，`updatedAt` 新者胜（LWW）；墓碑清单中的 id 直接过滤；
2. 本机删除写入 tombstones（30 天过期，每轮合并时修剪）；
3. 推之前先算整体状态指纹 `_stateHash(fragments, tombs)`（碎片全字段序列化排序 + 墓碑，顺序无关）：
   - 与 `syncStateHash` 一致 → **跳过 PATCH**（双方都没新内容，空闲轮询不再整包上传近 1MB）；
   - 不一致 → 全量序列化加密后 PATCH（已有）或 POST（新建），成功后记录指纹；
4. 本机改写 Gist 后清空 ETag（自己的 PATCH 让旧 ETag 失效，下一轮完整拉取做收敛）；`clearConfig()` 同时清 gistId/指纹/ETag，换账号不串状态。

**V1.4.4 可靠性补丁（2026-10-31）**：
- **排队不丢弃**：`sync()` 忙时不再 `return 'busy'` 丢掉触发，而是置 `_pending`（含是否手动），`finally` 里 400ms 后自动补跑一次——手机多次点同步或边传边记不再白等 45 秒轮询；
- **失败可见**：`cloudSync.lastError` 记录失败原因，按钮显示「☁ 待同步」、title 写明原因，下次成功自动恢复；自动同步失败用 5 分钟同错节流 toast（此前自动同步完全静默）；
- **增量写库**：合并结果改用 `db.applyMerge(items, deadIds)`（按 id `put` + 只 `delete` 墓碑 id），替代 `replaceAll` 的"整库 clear 再重写"——后者在"合并窗口内刚好封存新碎片"时会把那条冲掉。
- **尚未解决**：主同步文件仍内嵌图片 base64（2026-10-31 已达 1.48MB），单次同步要整包下载+整包上传，手机耗时数分钟。根治方案见 `docs/02` 提示词 V1.5.1（索引与附件分文件）。

**为什么不用 CRDT**：碎片以短文本为主，同一条在两台设备并发编辑的概率极低；Yjs/Automerge 会带来状态向量与历史膨胀。LWW+墓碑是 TriliumNext（约 3.9 万星开源笔记）经大规模验证的同款方案。唯一已知边界：同一碎片两设备断网并发编辑，保留较新版本（可接受，已写入文档）。

### 5.4 自动同步时机（V1.3.5 实际）

| 时机 | 延迟 |
|---|---|
| 启动后 | 1.5 秒 |
| 封存/删除/导入等本机改动 | 5 秒防抖 |
| 恢复联网（online 事件） | 1.5 秒 |
| 回前台（visibilitychange）/窗口获焦 focus / pageshow | 约 1.2 秒 |
| 页面持续可见时定时轮询 | 每 **45 秒** |
| 手动点「☁ 云同步」 | 立即 |

未配置令牌时以上全部静默不发请求。所有 Gist 请求带 `cache:'no-store'`——GitHub API 响应带 60 秒缓存许可，不禁止缓存会让轮询慢一个周期（v1.3.5 实测发现）。

### 5.5 已知扩展条件（留给后续版本）

- 信封 `v` 字段：加密算法升级口；
- `updatedAt` + tombstones：V2.0 的关联/剥离自动获得同步能力；
- 写放大：单文件全量写，密文到 MB 级后可拆"索引/附件/墓碑"多个 Gist 文件（Joplin item 协议思路），列为 V3.0 候选；
- Gist 不是媒体托管：图片继续靠 Canvas 压缩控制体积；音频坚持外链。

## 六、渲染层关键点

### 6.1 瀑布流（V1.3.4 重写，V1.4.1 定型）

- 结构：`.masonry` 为 flex 容器，JS 按**容器实际宽度**（≤600px 一列、≤1024px 两列、否则三列）建列 div，卡片逐张放入**当前 scrollHeight 最矮的列**，入列后不再移动。
- 图片不跳动（V1.4.1）：压缩时把宽高存入 `imageW/imageH`，图片容器 `.card-img-wrap` 直接设 `aspect-ratio`，卡片插入时高度就是准的；旧数据缺尺寸则在图片 load 后只补写**本卡**比例，不影响其他卡片。已删除 v1.3.4 的"load 后跨列重平衡"——它正是"卡片飞到别的列又回来"闪烁的根因。
- 列数重建（V1.4.1）：ResizeObserver 观察容器宽度，仅在跨断点时重建；抽屉开合动画期间不重建（守卫 `state.drawerId`），横竖屏旋转才重排。
- 为什么不用 CSS `column-count`：iOS Safari（含 iPadOS）对多列布局内动态插入的内容长期存在渲染丢失——碎片增多后右侧列卡片整块画成白块，只剩绝对定位的删除叉，WebKit 多年未彻底修复。这是真机（非模拟器）发现的问题。
- 抽屉让位（V1.4.1）：桌面/平板抽屉打开时 `body.drawer-open` 让顶栏与瀑布流 padding-right 让出 `--drawer-w`（clamp(340px,40vw,580px)，与抽屉同变量）。手机端（V1.4.3）底部抽屉为两档：默认 44vh、`.drawer.full` 时 92vh，列表 padding-bottom 随之切换；顶部抓条 `#drawerGrabber` 与 ˄/˅ 按钮调用 `render.toggleDrawerSize()`，openDrawer 每次重置为半屏。背景不遮罩、可滚动且不被盖住。刻意不做小红书式双列：长文字卡在窄双列中阅读拥挤。
- 空状态用 flex:1 1 100% 跨列。

### 6.2 安全渲染

全部用户内容走 `createElement` + `textContent`；XSS 测试串 `<script>alert(1)</script>` 原样显示。**V1.4 已实现的链接渲染沿用同一原则**：`render.linkedText()` 用正则只切出 http/https 候选，再经 `new URL()` 协议白名单二次校验，`<a target="_blank" rel="noopener noreferrer">` 且点击 `stopPropagation` 防误开抽屉；`javascript:`/`data:` 等一律落回纯文本节点。链接不改写 `content` 原文，因此搜索、导出、加密同步零影响。

### 6.3 PWA 与更新策略

- `manifest.webmanifest`：standalone、图标 192/512、apple-touch-icon；
- `sw.js`（缓存名随版本 `inspiration-inbox-vX.Y.Z`）：**HTML/manifest/导航请求网络优先**（保证用户能收到更新），静态资源缓存优先；安装阶段预缓存；
- 更新提示：新 SW 等待中 → toast「🔄 发现新版本，点此立即更新」→ postMessage SKIP_WAITING → controllerchange 自动 reload；
- 教训（V1.2）：SW 若对 HTML 用 cache-first，用户三端永远收不到更新；测试浏览器需先 unregister + caches.delete 才能加载新版。

### 6.4 安装引导（V1.3.1–1.3.3）

- `beforeinstallprompt`：安卓/桌面可内弹安装；iOS Safari 不触发该事件；
- 安装按钮在独立显示模式（standalone）下隐藏；iOS 上常驻并弹图文指引（Safari 分享 → 添加到主屏幕）；
- 安卓调用后 4.5 秒未见 outcome 成功则弹手动步骤（含华为/出境易容器权限说明）；
- iOS 独立数据容器：Safari 标签页、Chrome/Edge、主屏幕 App 各自 IndexedDB 互不相通，靠云同步或导出/导入搬家。

## 七、八步搭建/重建法（给 AI 的施工顺序）

1. 骨架与 `<style>` 设计令牌（CSS 变量日夜两套）；
2. 第 1–3 层：常量、db（open 迁移、CRUD、settings）、state；
3. 录入区 + 封存写库 + 最粗糙列表渲染；
4. 三 Tab + 搜索 + 标签；
5. 瀑布流 + 卡片 + 抽屉（先 flex 分列，不要再用 columns）；
6. 图片压缩、主题、导入导出、自动备份；
7. PWA：manifest、sw.js、更新提示、安装引导；
8. 第 2B 层：云同步（加密 → Gist → 合并/墓碑 → 自动时机 → selftest）。

每层做完三端真机过一遍再进下一层。
